# 프로젝트 작성 정책

이 문서는 이 워크스페이스에서 문서, 주석, 스크립트 안내 문구를 작성할 때 따르는 기준을 정리한다.

## 1. 역할

- 이 문서는 `어떻게 쓸지`를 정한다.
- 제품 방향과 기능 범위는 `job_coach_onepager.md`가 정한다.
- API 구조, 필드명, 구현 로직, 테스트 전략은 이 문서가 직접 결정하지 않는다.

## 2. 인코딩과 저장 형식

- `SKILL.md`, `*.md`, `*.yaml`, `*.yml`, `*.py`는 `UTF-8 without BOM`으로 저장한다.
- `*.ps1`은 Windows PowerShell 호환을 위해 `UTF-8 with BOM`으로 저장한다.
- 개행은 `LF`를 기본으로 한다.
- 파일 마지막에는 개행을 남긴다.
- `SKILL.md`는 파일 첫 바이트부터 바로 `---` YAML frontmatter가 시작되어야 한다.

## 3. 한국어 작성 기준

- 사용자-facing 문구, 문서 본문, 주석, 스크립트 안내 문구는 한국어를 기본으로 한다.
- 한 문단에는 한 결론만 둔다.
- 긴 문장은 두 문장으로 나눈다.
- 한 줄에 생각을 여러 개 겹치지 않는다.
- 주어와 서술어를 앞쪽에 두고, 수식어는 뒤로 미룬다.
- 추상 표현보다 동작이 보이는 표현을 우선한다.

권장 예:

- `정리한다`
- `제안한다`
- `반영한다`
- `확인한다`
- `이어준다`

## 4. 용어와 표현

- 아래 고정 용어는 계속 같은 형태로 쓴다.
  - `취업 코치형 에이전트`
  - `지원 준비 요약서`
  - `지원 대상 후보`
  - `실행 항목`
  - `피드백 반영`
- 같은 뜻의 말을 문서마다 바꿔 쓰지 않는다.
- 영어 토큰이 코드명, 필드명, 경로, 도구명인 경우 원형을 유지한다.
- 코드명, 필드명, enum 값, 경로는 backtick으로 감싼다.

## 5. 주석과 스크립트 규칙

- 주석은 `무엇`보다 `왜`를 설명한다.
- 자명한 코드는 주석을 남발하지 않는다.
- 스크립트 파일명은 영어 ASCII로 유지한다.
- 스크립트 상단 설명과 콘솔 안내 문구는 한국어로 쓴다.
- 에러 메시지는 짧고 바로 행동이 보이게 쓴다.

## 6. 정책 적용 대상과 예외

이 정책은 아래 대상에 우선 적용한다.

- `md`
- `yaml`, `yml`
- 코드 주석
- docstring
- 스크립트 안내 문구

이 정책을 아래 대상에 그대로 적용하지 않는다.

- Pydantic 필드명
- `Literal` 값
- route path
- 환경 변수명
- JSON payload 키
- error code

즉, 실행 코드와 API 계약은 번역하거나 바꾸지 않는다.

## 7. 확인 방법

- Windows PowerShell에서는 `Get-Content -Encoding utf8`로 파일을 확인한다.
- `SKILL.md`는 BOM 없이 시작해야 한다.
- 깨진 한글이 보이면 기본 인코딩 표시 문제인지 먼저 확인하고, 실제 파일 바이트를 점검한다.
