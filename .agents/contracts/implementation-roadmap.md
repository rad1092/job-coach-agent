# 구현 로드맵

이 문서는 구현 순서를 고정한다.
`current-status.md`가 현재 상태를 적는 문서라면, 이 문서는 다음 단계와 종료 조건을 적는 문서다.

## 1단계: 프론트 연결 `완료`

- 목표:
  - LangGraph 백엔드를 사용자가 한 번 끝까지 써볼 수 있게 만든다.
- 우선 작업:
  - `frontend/app.py` 추가
  - 입력 단계 구현
  - 후보 탐색 결과 표시
  - `지원 준비 요약서`와 문서/면접/일정 결과 표시
- 시작 조건:
  - 백엔드 API와 테스트가 이미 동작할 것
- 종료 조건:
  - `frontend/app.py`가 구현되고 화면 흐름이 코드 기준으로 닫혀 있을 것

## 2단계: 실행 흐름 정리 `완료`

- 목표:
  - 백엔드와 프론트를 바로 켤 수 있게 만든다.
- 우선 작업:
  - `scripts/run_backend.ps1`
  - `scripts/run_frontend.ps1`
  - `scripts/smoke_real.ps1`
- 시작 조건:
  - 프론트가 최소 동작할 것
- 종료 조건:
  - 백엔드, 프론트, 스모크 실행 스크립트가 모두 준비될 것

## 3단계: 실제 키 검증 `완료`

- 목표:
  - fixture가 아니라 실제 `OpenAI + Tavily`로 품질을 본다.
- 우선 작업:
  - 프론트 수동 흐름 기준 품질 확인
  - `지원 준비 요약서` 품질 확인
  - 산출물 일반론 여부 확인
  - 응답 시간 확인
- 시작 조건:
  - 프론트와 실행 스크립트가 준비될 것
- 종료 조건:
  - 최소 2개 시나리오에서 end-to-end 결과를 확인할 것

## 4단계: 백엔드 보정 `현재 단계`

- 목표:
  - 실키 결과를 보고 최소 보정만 한다.
- 우선 작업:
  - 탐색 쿼리 분리와 relevance 보정
  - 공고/회사/참고 정보 분류 기준 보정
  - 프롬프트 미세 조정
  - warning 문구 정리
  - critic 조건 보정
- 시작 조건:
  - 실키 검증 결과가 있을 것
- 종료 조건:
  - 결과가 너무 일반적이거나 데모에서 어색한 지점이 줄어들 것
  - 2단계 후보가 지원 대상 기준으로 더 정밀해질 것

## 최근 반영 사항

- 2단계를 `공고 우선 단일 선택`으로 정리 완료
- 3단계 결과를 `요약 + 실행 항목 + 면접` 구조로 단순화 완료
- `일정 항목` 제거 완료
- `.gitignore` 추가 완료
- 루트 `README.md` 실행 문서 작성 완료
- `smoke_real.ps1` 현재 계약 동기화 완료

## MVP+ 이후

- 사용자 메모 저장과 반영
- 메모/DB 레이어
- 장기 세션 상태
- LangGraph 노드 확장
- 더 정교한 evidence judge

## 자동 업데이트 방향

- 단계가 끝나면 다음 단계로 한 칸 올리고, 이전 단계는 완료로 표시한다.
- 새 우선순위가 생기면 `우선 작업`을 갱신한다.
- 시작 조건이나 종료 조건이 바뀌면 이 문서를 먼저 수정한다.
- 구현을 진행하는 에이전트나 사람이 다음 작업을 시작할 때는 이 문서를 먼저 읽고, 작업을 끝낸 뒤 `current-status.md`와 함께 같이 갱신한다.
